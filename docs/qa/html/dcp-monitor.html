Council document monitor

How the system notices when a council changes its planning documents. Traced from code at commit a6d2e378 (24 Oct 2026).

Councils change their development control plans without telling anyone. Every night the monitor visits each council's document list page and checks it for new, removed or changed links. It then checks each document: a cheap header check first, and a full download only when something looks different. Changed files are saved, and every outcome is recorded.

A separate alarm runs each evening and reads those records. If a run did not happen, stopped half-way, or a council has not been checked recently, it sends an alert. A silent failure turns into a visible one.

Known weak points (for the review)

  • If the scraper code fails to load, the monitor logs every council as “no scraper” instead of crashing. That is a quiet failure.
  • The general-purpose run recorder imports a helper from one council's scraper (Inner West).
  • The job image lists about 70 files one by one. Its own comments record past breakages from a missed file.
  • Per its config, a weekly extraction job is now the main change detector. That job is not shown here.
