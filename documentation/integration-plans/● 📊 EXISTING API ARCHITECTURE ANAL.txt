● 📊 EXISTING API ARCHITECTURE ANALYSIS

  🔍 Current Planning API Flow:

  1. Main Property API:
  - Route:
  /api/property?address=30+Illawarra+Road+Marrickville
  - Service:
  PropertyDataService.getPropertyComplianceData(address)
  - Speed: "couple of seconds at least" (NSW Planning
  Portal calls)
  - Returns: Basic property data + constraints

  2. Current Response Structure:
  {
    propId: number,
    address: string,
    constraints: {
      maxFsr: 0.6,
      maxHeight: 9.5,
      zone: "R2",
      heritage: boolean,
      // ... other constraints
    },
    fsrSource: {
      clause: "4.4",
      epiName: "Inner West LEP 2022",
      legislationUrl: "..."
    },
    heightSource: {
      clause: "4.3",
      epiName: "Inner West LEP 2022",
      legislationUrl: "..."
    }
  }

  3. Current UI Flow:
  - User enters address in QuickSearch component
  - Calls /api/property → takes several seconds
  - Shows results in PropertyCard component
  - Has "View Full" buttons that link to NSW Planning
  Portal URLs (external)

  🎯 MVP SOLUTION:

  New Separate Action Button:

  "📋 View Legal Text" button in right pane that:

  1. Takes the existing fsrSource.clause and
  fsrSource.epiName
  2. Maps to our corrected database via new route
  3. Shows full legal text from documents.full_text
